# Цели Яндекс.Метрики, которые надо завести

Счётчик **112091538**. Цели создаются вручную в интерфейсе Метрики — код уже
отправляет события с этими именами. Тип цели во всех случаях —
**JavaScript-событие**, идентификатор совпадает с именем ниже.

На `localhost` отправка выключена принудительно (`src/metrics.js`), чтобы свои
прогоны не топили выборку.

### Что означают параметры

| Параметр | Где | Что это |
|---|---|---|
| `sec` | у всех | секунды от загрузки страницы до события |
| `read` | `term_read_N` | **секунды, проведённые на карточке термина** — прямая проверка потолка плотности |
| `term` | `quiz_answer` | id термина, о котором спросили (`cornice`, `archwindow`, `ibeamb`, `terracing`, `block`) |
| `ok` | `quiz_answer` | 1 — ответ верный, 0 — неверный |
| `right` | `finish` | сколько ответов из пяти узнано с первого раза |

## Что делать в интерфейсе: три переименования и шесть новых целей

### 1. Переименовать (идентификатор НЕ трогать, меняется только название)

| Идентификатор | Было | Стало |
|---|---|---|
| `zone_done_1` | 04 · Собрал карниз | **04 · Направление: архитектура** |
| `zone_done_2` | 05 · Собрал арочное окно | **05 · Направление: ландшафт** |
| `zone_done_3` | 06 · Собрал двутавр | **06 · Направление: дизайн среды** |

Названия стали неверными: под `zone_done_1` теперь не «собрал карниз», а
«закрыл всё направление архитектура» — три станции сразу. Если названия не
поправить, отчёты будут врать не цифрами, а подписями, и это хуже.

### 2. Создать шесть новых

Тип — **JavaScript-событие**, идентификатор ровно как в колонке.

| Название | Идентификатор |
|---|---|
| 13 · Направление: реставрация | `zone_done_4` |
| 14 · Направление: градостроительство | `zone_done_5` |
| 15 · Карточка: террасирование | `term_read_4` |
| 16 · Карточка: МАФ | `term_read_5` |
| 17 · Карточка: консервация | `term_read_6` |
| 18 · Карточка: квартал | `term_read_7` |

Существующую нумерацию 01-12 менять не нужно: Метрика сортирует список по ID,
а номер в названии — только для чтения глазами.

### 3. Ничего не делать

`gate_mobile`, `start`, `frag_first`, `term_read_1..3`, `quiz_answer`, `finish`,
`replay` — смысл не менялся, названия верны. Автоцель «клик по email» к игре
относится (в мобильной заглушке есть кнопка «Отправить себе письмом») и
тоже не трогается.

## ВАЖНО: у `zone_done_2` и `zone_done_3` изменился смысл

Это единственное место, где новые данные **нельзя** складывать со старыми.

Раньше зона = элемент, зон было три:

```
zone_done_1 = собран карниз
zone_done_2 = собрано арочное окно
zone_done_3 = собрана двутавровая балка
```

Теперь зона = **направление профессии**, их пять, а станций сборки семь:

```
zone_done_1 = архитектура        (карниз + арочное окно + двутавр — все три)
zone_done_2 = ландшафт           (террасирование)
zone_done_3 = дизайн среды       (МАФ)
zone_done_4 = реставрация        (консервация)
zone_done_5 = градостроительство (квартал)
```

**Что с этим делать:** отсечь историю `zone_done_1..3` по дате выкладки новой
версии и считать эти три цели с нуля. `zone_done_1` при этом стал строже старого
(требует трёх сборок вместо одной) — падение конверсии по нему в первый же день
ожидаемо и не является ухудшением продукта.

Я сознательно **не переименовывал** цели в `dir_done_*`: бриф 3.7 просит
`zone_done_4..N`, и заводить рядом второй ряд имён ради чистоты одной серии —
дороже, чем один раз отсечь историю.

`term_read_1..3` менять смысл **не** меняли: это по-прежнему карниз, арочное
окно и двутавр в том же порядке. Эти три серии сравнимы со старыми напрямую.

## Что мерить в первую очередь

Потолок плотности текста (бриф 3.4) проверяется не на глаз, а по параметру
`read` — числу секунд на карточке. Он уже отправляется с каждой `term_read_N`.

**Признак того, что терминов слишком много:** медиана `read` на поздних
карточках (`term_read_5..7`) заметно ниже, чем на ранних (`term_read_1..3`).
Это значит, что текст листают, а не читают, — и тогда снимать надо термин, а не
сокращать определение.

Второй сигнал — разрыв между `zone_done_N` и `zone_done_N+1`: на каком
направлении теряется больше всего людей.

Параметр `sec` (секунды от загрузки) есть у всех целей — по нему собирается
хронометраж живых сеансов, которого мне взять было негде (см.
[ОТЧЁТ.md](ОТЧЁТ.md), раздел о хронометраже).
