# АРХИСБОР

**Платформер архитектурных терминов.** Метод — «форма раньше слова».
Месседж — «архитектор не просто рисует дома».

Браузерный платформер-тренажёр: абитуриент собирает по фрагментам архитектурные
элементы и запоминает термин через форму, а не через определение. Один уровень,
один сеанс ~10–12 минут, **пять зон = пять направлений профессии**, семь терминов:

| Зона | Направление | Термины |
|---|---|---|
| 1 | архитектура | карниз, арочное окно, двутавровая балка |
| 2 | ландшафт | террасирование |
| 3 | дизайн среды | малые архитектурные формы (МАФ) |
| 4 | реставрация | консервация |
| 5 | градостроительство | квартал |

Каждая зона — свой визуальный характер: грунт, задник, свет и наполнение
различаются, зону видно с одного взгляда.

Замысел, принятые решения и премортем живут в рабочих материалах проекта и в
репозиторий не входят. Отчёт о последней доработке — в `handover/`.

## Запуск

Нужен любой статический сервер (Phaser грузится с файлами — можно и `file://`, но сервер надёжнее):

```
cd game
python -m http.server 8137
# → http://localhost:8137
```

Сборка не нужна: без бандлера, без npm. Вся графика и звук генерируются кодом,
Phaser 3.87 лежит локально в `vendor/`. Единственное внешнее подключение —
фирменные шрифты (Google Fonts и Tilda CDN): решение автора, у обоих системный
фолбэк, недоступность CDN меняет вид оболочки, но не ломает игру.

## Деплой

**Прод: https://art-brodsky-start-minigame.vercel.app/**

Статика на Vercel из ветки `main`: `vercel.json` задаёт `outputDirectory: "game"`,
так что корень репозитория деплоить не нужно. GitHub public → Vercel, без сервера
и базы.

Кэш скриптов ручной: в `index.html` у каждого `<script>` стоит `?v=N`. **После
каждой правки в `src/` номер надо поднять**, иначе браузер отдаст старый файл.

## Устройство

```
game/
  index.html              разметка, стили оверлеев, порядок скриптов
  vendor/phaser.min.js    Phaser 3.87 локально
  src/
    content.js            КОНТЕНТ: пять зон-направлений, семь элементов (имя,
                          определение, пути силуэта, слоты сборки, дистракторы),
                          дистракторы проверки + два захардкоженных тоста
    draw.js               рисование полигонов-колец на canvas/svg, палитра
    textures.js           процедурные текстуры: автотайлсет 16 масок × 5 тем,
                          игрок (6 поз), пять комплектов задников, фрагменты, слоты
    ui.js                 DOM-оверлеи: мобильный гейт, тосты, карточки термина,
                          пауза, викторина узнавания, финальный экран
    scenes/PlayScene.js   ГЕОМЕТРИЯ уровня (таблица LEVEL: колонки, платформы,
                          пикапы, доски, стены), игрок, сбор, сборка кликом,
                          расстановка МАФ, стены прогресса, викторина
    main.js               конфиг Phaser: arcade-физика, FIT-масштаб
```

**Где что менять.** Термины, определения, формы и состав зон — только
`content.js`. Расположение платформ и станций — таблица `AG.PlayScene.LEVEL()`.
Геометрия намеренно не ушла в данные: уровень по-прежнему один, а обобщать до
второго случая проект не обобщает (принцип 8).

## Как это соответствует скоупу

- **Форма раньше слова**: название появляется только после ручной сборки силуэта и секунды тишины.
- **Сбор**: фрагменты копятся в панели справа без текста; как они соберутся — не видно.
- **Сборка**: раз на станцию, клик по фрагменту → клик по месту; промах не наказывается.
- **Вариация ритма в зоне МАФ**: собираются не фрагменты одной формы, а четыре
  готовых предмета, и расставляются по скверу. Каждый при установке называет себя
  одной строкой; общий термин раскрывается карточкой в конце зоны.
- **Проверка**: в конце вопрос называет термин, игрок выбирает форму из четырёх
  похожих; ошибка не блокирует — показывается правильный.
- **Бюджет внимания**: 7 карточек термина + максимум 2 тоста за сеанс
  (счётчик `toastBudget` в `ui.js`), «показан один раз» живёт в памяти сеанса.
  Потолок плотности — не чаще одной карточки на 85 секунд; учебного текста за
  сеанс 245 слов при потолке ~250, все определения по 25–30 слов.
- **Без врагов, смерти, таймера и очков.** Промах по прыжку роняет на уступ ниже;
  в ландшафтной зоне из промоины выбрасывает пружина.
- **Мобильные**: экран «открой на компьютере» с копированием ссылки.
- **Титульный экран** поверх живого мира: название, что собираем, сколько занимает
  и что нужна клавиатура — видно, не запуская. Это же первый экран для
  преподавателя, который решает за десять секунд, давать ли это группе.

## Звук

Синтезируется на Web Audio, ни одного файла — тот же принцип, что и с графикой.
Палитра чиптюновая: короткие прямоугольные волны и скольжения частоты. Подбор
фрагмента звучит «монеткой» — деталь, по которой ухо мгновенно опознаёт жанр.

Громкость низкая осознанно (мастер 0.20): игра текстовая по нагрузке, звук не
имеет права спорить за внимание с определением термина. **M** — выключить,
состояние помнится между визитами. Разблокировка контекста — по жесту, при
уходе титульного экрана.

## Аналитика

Яндекс.Метрика считает **доходимость, а не усвоение**. Разделение взято из
премортема: «аналитику обучения» проект отверг сознательно, «счётчик открытий и
завершений» — оставил. Восемнадцать целей от `gate_mobile` до `finish`; у каждой
параметр `sec` — секунды от загрузки, чтобы видеть, на какой минуте теряем.
Полный список и что с ними делать — в `handover/ЦЕЛИ-МЕТРИКИ.md`.
Отдельно считается время на карточке термина: это прямой ответ на вопрос,
читают определение или пролистывают.

**Уведомление о сборе** показывается на титульном экране до начала игры: что
именно сохраняется (cookie и IP), чего не собирается (имя, телефон, почта) и
ссылки на политику обработки данных и публичную оферту школы. Те же ссылки — на
финальном экране и на заглушке для мобильных, то есть на всех трёх точках входа
и выхода.

Номер счётчика — единственная константа в `src/metrics.js`. При `null` не
грузится ничего; на `localhost` выключено принудительно, чтобы свои прогоны не
топили выборку. Выводов об усвоении по этим цифрам не делать — финальная
проверка завышает результат.

## Ощущение прыжка

Всё перечисленное убирает трение, а не добавляет сложности — иначе оно попадало бы
под запрет «ничего не добавлять без доказательства»:

- **coyote time** (110 мс) и **буфер прыжка** (120 мс) — прыжок срабатывает, если
  нажать чуть раньше края или чуть позже схода с него;
- **скольжение по стене и прыжок от неё** — с паузой 180 мс и запретом двух
  прыжков подряд от одной стороны. Оба ограничения не косметические: без них
  стену прогресса можно перелезть, а стена прогресса держит обучающую петлю;
- **площадки «сквозь низ», движущиеся платформы и пружины** — вертикальная
  планировка зон без единой механики, требующей тренировки;
- **переменная высота** — короткое нажатие обрезает подъём до −320;
- **подправка угла**: зацепил край платформы одним углом на пару пикселей — игрока
  сдвигает вбок и возвращает прыжок, а не гасит его;
- **камера смотрит вперёд** по ходу движения (до 120 px со сглаживанием);
- **пыль** под ногами на прыжке и жёстком приземлении, сплющивание спрайта.

## Что дальше (после плейтеста)

Порог успеха: из пяти живых школьников трое доходят до конца, не пролистывают текст
и проходят финальное узнавание.

**Самое срочное — снять живой хронометраж.** Расчёт даёт 9,8–13,4 минуты, то есть
верхняя граница выходит за потолок в 12 минут. Это единственная величина, которую
не удалось измерить: см. `handover/ОТЧЁТ.md`, раздел 2.3.

Второй уровень и обобщение геометрии в данные — только после того, как ядро
подтвердится на живых школьниках.
